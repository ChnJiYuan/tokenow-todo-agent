# 演示与提交整理

## 录制前

使用 Node 24.12+，`npm ci`、`npm run build`，在本地 `.env` 配置密钥。真实模型会产生调用费用。以下脚本从仓库根目录运行，自动创建独立临时目录与端口，不读取开发任务文件：

```sh
DEMO_PAUSE=1 LIVE_REPORT=reports/my-demo.json npm run verify:demo
```

脚本通过生产入口逐轮执行真实模型对话，核对完整状态和 API/磁盘；在真正重启前后暂停并打印浏览器地址。地址可能变化，按新地址打开。检查完后在终端回车继续；完成后自动清理临时数据。不要把该脚本的输入发到已有开发清单。

## 简短视频顺序

1. 说“记一下准备面试，今天到期，低优先级，工作量大。”
2. 说“给准备面试加个子任务：整理项目介绍，今天到期，高优先级，工作量小。”再加“练习自我介绍，今天到期，低优先级，工作量中”。
3. 说“今天有哪些任务到期？”，展示今日默认只包含未完成任务。
4. 说“把整理项目介绍改成中优先级、工作量大。”，展示子任务仍保留原ID、父任务和日期。
5. 先说“准备面试完成了。”，展示未完成子任务会阻止完成；再说“整理项目介绍做完了。”，展示主任务仍未完成。
6. 刷新页面。展示同一ID、父子关系、1/2进度、状态、日期、优先级和工作量。脚本停止并重新启动生产进程后，再按新地址展示同一份状态。
7. 完成另一个子任务，展示主任务不会自动完成；明确完成主任务。给已完成主任务新增“录制视频”子任务，展示主任务恢复未完成。
8. 说“删除准备面试。”，展示删除确认且数据未变；回复“确认一并删除 #主任务短ID”，展示父子整组删除、其他任务保留。

脚本还创建“检查设备”作为无关对照，查询优先级排序后编号应是4、1、2、3，父子仍相邻。真实模型的逐轮流程由脚本发送；浏览器用于展示和核对，不能称为所有步骤均由手工界面输入完成。本轮未录制视频，以上步骤供本人录制。

## 独立界面 mock

```sh
npm run preview:demo
```

该命令输出另一隔离地址，固定今天为 `2026-12-31`，不调用真实模型。默认编号1、2、3、4、5、6；按优先级分组展示后为5、6、1、2、4、3；今日到期为5、1、4；叠加高优先级和大工作量仅显示4，并保留所属主任务。将工作量改为中显示空态。检查完成后 Ctrl+C 清理临时目录。

## 待纳入提交的文件

工作区开始时已有日期、属性、子任务等未提交功能；应连同必要的新模块、测试、文档、脚本与报告整体复核，不只提交本轮规划器修改。精确文件清单见 `reports/completion/submission-files.json`；其中 `existing` 表示开始时已有改动，`addedThisRun` 表示本轮新增，`modifiedThisRun` 表示本轮接续修改。`SUBMIT.md` 保留原有改动，排除在本轮自动整理范围外，由本人决定是否纳入最终提交。

建议提交信息：

```text
feat: finish task extensions and align missing-target contract
```

可以在同一次提交中包含日期、一级子任务、属性和展示扩展、缺失目标修复及验收证据，避免漏掉目前未跟踪的新模块。未自动暂存、提交或推送，也未发送邮件。

## 本人需更新 SUBMIT.md

- 将“未实现到期日期、子任务、优先级和工作量”改为四项明确扩展均已实现；定时提醒/发送通知仍未实现。
- 补充主任务完成阻塞、不自动完成、已完成主任务恢复、删除确认和一级级联规则。
- 补充服务端时区、日历日期、今日查询默认未完成、属性默认中/中及不继承、父子分组排序和编号保持。
- 将37项测试改成本轮最终检查报告的数量；真实模型、浏览器mock和历史结果分别说明，引用 `docs/VERIFICATION.md`。
- 更新验证命令及串联演示方式，说明真实进程重启、完整字段/ID一致性和隔离数据。
- 将“日期和子任务扩展应先明确……”的未来计划改为已实现规则，保留多层子任务、定时通知、单进程JSON和内存幂等的限制。
- 亲自复核 AI 辅助说明、仓库链接及全部结论；本轮没有编辑该文件。
