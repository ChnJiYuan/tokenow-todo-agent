# 高干扰真实对话测试

最终整集：**54个场景、65轮真实对话全部通过，0错误写入、0模型错误、0跳过**；37项离线测试通过。最终报告的核心代码、案例和判定器 SHA-256 已与当前文件核对一致。

## 如何运行

需要 Node 24.12+ 和本地 `.env` 中的有效 DeepSeek API Key。以下命令会产生真实模型费用，不在无密钥 CI 中自动运行。

```sh
npm run verify:dialogues
```

场景在 `scripts/dialogue-cases.ts` 中，执行器在 `scripts/verify-dialogues.ts` 中。通过生产入口启动独立服务，使用临时文件和端口；不访问开发任务，不占用3000端口。场景之间通过任务 API 重建数据，每个场景内保留完整对话历史。

默认结果写入 `reports/live-dialogues-latest.json`。筛选和重复执行示例：

```sh
LIVE_CASES=failed-pickup,negated-position LIVE_REPEATS=2 LIVE_REPORT=reports/my-run.json npm run verify:dialogues
```

`LIVE_CASES` 使用场景ID，未知ID会被拒绝；`LIVE_REPEATS` 只允许1至3。默认结果文件会覆盖，用 `LIVE_REPORT` 保留不同轮次。

## 固定预期和通过条件

测试覆盖否定与条件、模糊指代、同名和近义任务、口语和中英混合、反讽、操作咨询、多意图、引用文字、标题注入、伪列表编号、未知ID、超长标题和未实现能力。

- “先别删”“还没完成”、示例引用和未来条件：保留任务。
- “牛奶那事算了”：可能是取消对话或暂缓，先询问，不直接删除。
- 任务未达成却说“划掉”：询问删除还是完成；明确说删除未完成任务时可以执行。
- 最近唯一任务的指代：正常执行；最近提到多个对象时先澄清。
- 句子同时否定第一条、肯定第二条：只操作明确的第二条。
- 多意图和批量操作：本题只支持一轮一个操作，要求拆分。
- JSON或命令出现在明确标题中：按原文记录，不执行里面的命令，也不拼接标题外解释。

每轮同时检查：回复类型、清单顺序和标题、完成状态、原任务ID保持不变，以及API与磁盘一致。筛选查询还检查回复包含和排除的标题。只保持数据不变但返回模型错误、格式错误或无关回复，不算通过。

某场景失败后跳过其剩余轮次，继续独立场景。基础设施中断会标记错误和未完成数量，退出码为1，不把未完成场景记成通过。

历史记录也保留了旧判定器将“请缩短标题”误分为unknown的原始失败案例；实际回复和存储符合业务预期。已修正判定器并补回归，没有降低业务预期。完整中间运行日志保留在本地被Git忽略的 `data/live-dialogue-history/`，仓库提交摘要及原始失败案例，避免重复提交多份相同的成功轨迹。

已针对发现的问题加强规划器对成功事实、取消、含糊操作词和原文标题的约束，补强唯一最近指代；执行器支持核对句子中的多个编号，并拒绝伪造同号列表行。超长标题返回明确的参数澄清。对应的编号与标题反馈逻辑有离线回归测试。

## 解释结果时的边界

这些是人工设计的固定合成案例，包含针对发现问题的回归和后续改写对照。通过固定案例不代表所有中文表达都可靠；语义修复主要依赖模型提示词，不是对任意坏模型输出的确定性安全证明。

回复类别采用规则粗分，仍需人工检查澄清是否切合问题。最终报告中的澄清已逐项抽查；任务状态与ID断言独立于文字分类，模型报错和不相关陈述不算成功澄清。

记录的 `durationMs` 包含该轮HTTP请求及状态核对，不是纯模型推理耗时；目前不据此给出性能承诺。记录的是对话轮数，不是底层模型请求数，每轮仍可能因空白/非法JSON触发一次规划重试。未统计总token和账单金额。
