# 小明智能体 · 待办清单编程题

基于 [TokeNow/todo-agent](https://github.com/TokeNow/todo-agent) 模板实现的中文待办智能体。

当前已实现创建、查询、完成和删除主任务及一级子任务；复用本地 JSON 持久化，增加任务面板、状态筛选、歧义澄清和请求去重。模型负责生成结构化计划，服务端校验并执行，回复来自真实执行结果。无需新增依赖。

四项明确的可选扩展均已实现：到期日期、一级子任务、清单展示、优先级和工作量。其中属性扩展支持优先级（高/中/低）和工作量（小/中/大）。工作量由用户粗略估计，不代表固定工时。每次新建时未指定的属性及缺字段的旧任务均按中处理，不从同名任务、父任务或历史继承，读取旧文件无需迁移。可以用中文创建、单独修改或同时修改同一任务的两项属性：

- “记一下准备面试，高优先级，工作量大。”
- “把准备面试的工作量改成中。”
- “把买牛奶改成低优先级、工作量小。”
- “列出高优先级且未完成的任务。”
- “有哪些工作量小的任务？”

查询由执行器按真实字段筛选。面板可组合状态、优先级、工作量筛选；默认保留父子分组，勾选“高优先级优先”后在主任务之间、同一父任务的子任务之间稳定排序，父子保持相邻，同优先级保持原顺序。面板使用 #短ID 定位；聊天中的“第几条”以最近一次聊天展示的清单为准。明确“紧急/最高优先级”可设为高；属性或对象不确定时先澄清，不根据标题猜测工作量。

## 运行当前项目

需要 Node.js **24.12.0 或更高版本**（`.nvmrc` 指定 24.12.0）。

```sh
git clone https://github.com/ChnJiYuan/tokenow-todo-agent.git
cd tokenow-todo-agent
npm ci
cp .env.example .env
# 在本地 .env 填写 DEEPSEEK_API_KEY，默认 DEEPSEEK_MODEL=deepseek-flash
npm run dev
```

打开 <http://127.0.0.1:3000>。未配置密钥时，聊天会提示配置方法，不会假装执行；任务 API 和清单面板仍可使用。已存在 `.env` 时请直接编辑，不要覆盖。

```sh
npm test
npm run typecheck
npm run lint
npm run fmt:check
npm run build
# 汇总上述检查和 git diff --check，保留每项输出与源码哈希：
npm run verify:checks
# 配置密钥后单独运行，会产生少量真实模型调用费用：
npm run verify:live
# 更多高干扰真实对话（需要密钥，会产生模型调用费用）：
npm run verify:dialogues
# 到期日期真实模型验收（固定服务端日期、隔离数据，同样需要密钥并产生调用费用）：
npm run verify:due-dates
# 优先级和工作量扩展的18轮真实模型验证（需要密钥，会产生调用费用）：
npm run verify:attributes
# 日期/属性/子任务组合演示，含真正的生产进程重启：
npm run verify:demo
# 浏览器专用固定日期/固定数据 mock（不调用模型）：
npm run preview:demo
```

自动测试不调用模型，全部使用临时任务文件。`verify:live` 启动独立生产服务，检查官方六步对话、磁盘状态、刷新后的空历史、真实进程重启、洗衣服场景及最近任务指代，并自动清理测试数据。

真实模型脚本支持 `LIVE_REPORT=reports/my-run.json` 指定报告路径，避免覆盖既有证据；全部使用隔离任务文件。`verify:demo` 可加 `DEMO_PAUSE=1` 在重启前后暂停，按输出地址打开浏览器，检查后回车继续。视频步骤见 [演示与提交整理](docs/DEMO.md)，本轮证据见 [验证记录](docs/VERIFICATION.md)。

`verify:dialogues` 进一步验证否定、模糊指代、反讽、同名、多意图和指令干扰，保留逐例JSON结果及失败基线，见 [高干扰真实对话测试](docs/DIALOGUE_TESTS.md)。

详细配置见 [本地开发指南](GETTING_STARTED.md)。实现讲解和已知限制见 [工程说明](docs/ENGINEERING.md)，实际执行结果见 [验证记录](docs/VERIFICATION.md)。[提交说明](SUBMIT.md) 使用 AI 辅助整理，提交前由候选人复核。

## 一级子任务扩展

连续对话示例：

1. “帮我记一下准备面试。”
2. “给准备面试加个子任务：整理项目介绍。”
3. “再加一个子任务：练习自我介绍。”
4. “准备面试还有哪些子任务没完成？”
5. “整理项目介绍做完了。”
6. “把准备面试和它的子任务一起删除。”

明确删除或完成的目标不存在时，规划器返回对应操作及空候选，执行器固定回复“没有找到对应的任务，本轮没有修改任务”，不选择无关任务；只有对象、指代或操作不明确时才澄清。

同名主任务或目标不明确时先澄清，可用清单的全局编号或 `#短ID` 选择。“再加一个子任务”依赖当前页面中最近唯一明确的主任务；刷新后请重新指定父任务。子任务用稳定的 `parentId` 关联，主任务重命名不影响关系。仅支持一级，不允许不存在的父任务、自引用、循环及子任务作为父任务。

主任务还有未完成子任务时，拒绝直接完成并列出待处理项；子任务全完成后，主任务仍需明确完成。给已完成主任务新增未完成子任务，会在同一次文件保存中恢复主任务。删除有子任务的主任务先询问，可回复“确认一并删除 #编号”；明确说“和它的子任务一起删除”可直接级联，整组只保存一次。删除单个子任务保留主任务。

面板缩进显示父子分组，主任务显示完成进度；筛选后子任务仍显示所属主任务及其 ID。聊天和面板共用父子分组的全局编号，筛选、排序不重新编号；优先级在主任务之间及同一父任务的子任务之间排序，父子保持相邻。增删任务后编号可能变化，执行器会核对历史清单中的编号到 ID 的映射，建议优先使用 `#短ID`。

REST 用 `POST /api/tasks` 的 `{ "title": "整理项目介绍", "parentId": "完整主任务ID" }` 创建子任务，`GET /api/tasks?parentId=完整主任务ID&status=pending` 查询；完成和删除仍使用子任务真实 ID。`PATCH` 支持修改 `parentId`，用 `null` 解除关系，所有关联均经服务端校验。删除含子任务的主任务默认返回409，只有 `DELETE /api/tasks/:id?cascade=true` 才级联。旧 JSON 无父任务字段时按主任务读取，未知扩展字段保留。完整契约见 [OpenAPI](server/openapi.yaml)。

子任务自动测试见 `server/subtasks.test.ts`，使用真实临时文件及 HTTP、模型边界 mock；未把 mock 结果当作真实模型自然语言验收。暂不支持多层子任务、聊天批量创建/移动子任务或跨进程共享 JSON 写入。

## 到期日期扩展

支持“明天之前要买牛奶，帮我记一下。”“把买牛奶改成今天到期。”“今天有哪些任务到期？”和“取消买牛奶的到期日期。”。今日／明日到期查询默认只返回当天到期且未完成的任务；说“包含已完成”才一并显示。无日期任务和逾期任务不会混入今天到期。面板提供到期日期、未完成任务的逾期标记和“今日到期”筛选。

服务端通过 `.env` 的 `TASK_TIME_ZONE` 设置任务时区，默认 `Australia/Sydney`。使用有效 IANA 时区名称（如 `Asia/Shanghai`），修改后重启；无效配置会在启动时报错。相对日期由服务端按每轮请求开始的当前日期解析，跨午夜后下一轮会使用新日期，不使用模型或浏览器猜测的今天。

到期日期仅保存 `YYYY-MM-DD` 的真实公历日期（0001 至 9999 年），不保存时刻，也不发送通知。“明天之前”按明天到期记录，不承诺具体截止时刻；明确要求定时通知时会说明能力边界并询问是否只记录日期。缺少年份或截止日期不明确时先澄清。

REST 创建使用 `{ "title": "买牛奶", "dueDate": "2026-12-31" }`；`PATCH /api/tasks/:id` 使用 `{ "dueDate": "2027-01-01" }` 修改，`{ "dueDate": null }` 清除。`GET /api/tasks?dueDate=2026-12-31` 默认筛选未完成，可加 `status=all` 或 `status=done`。旧任务可无日期，其他扩展字段仍保留，完整契约见 [OpenAPI](server/openapi.yaml)。

日期自动测试使用可控时钟和模型边界 mock，覆盖悉尼跨午夜／跨年、闰日、夏令时、修改／清除、查询状态和非法输入不写入；这些测试不能替代真实模型语义验证。

## 原题说明

请把小明改造成一个待办清单智能体，让用户用中文对话管理自己的任务。项目已经提供聊天界面、可持久化的任务 API 和 DeepSeek 客户端。

模板原始版本的智能体返回固定欢迎语；当前实现已替换这一行为。

## 基础要求

请让用户能通过聊天完成创建、查看、标记完成和删除这四种操作。任务应保存到本地，刷新页面或重启服务后仍可查询。

可以从 [server/agent.ts](server/agent.ts) 开始，在这里接收对话历史并返回本轮回复。

任务接口的路径、字段和返回值见 [OpenAPI 说明](server/openapi.yaml)。

下面是一段验收对话。

| 用户对小明说     | 预期结果                                   |
| ---------------- | ------------------------------------------ |
| 帮我记一下买牛奶 | 新增待办「买牛奶」                         |
| 再记一条取快递   | 清单里多了一条「取快递」                   |
| 我有哪些任务？   | 列出两条任务，并能看出各自的完成状态       |
| 牛奶买好了       | 把「买牛奶」标记为已完成，「取快递」仍待办 |
| 取快递这条删掉吧 | 删除「取快递」                             |
| 再给我看看清单   | 只剩已完成的「买牛奶」                     |

## 可选扩展

以下扩展功能可选做，有的任务描述刻意写得比较模糊。

- 回答「今天有哪些任务到期？」
- 创建并管理子任务
- 改进清单的展示，让用户更容易看出哪些任务还需要处理。
- 为任务增加优先级和工作量（如小、中、大）。
- 你认为合适的任何功能或优化
